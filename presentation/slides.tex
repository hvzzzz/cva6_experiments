\framesubtitle{A 6-stage RISC-V Open-Source core}
\begin{columns}
\begin{column}{0.5\columnwidth}
\begin{itemize}
\item \small Industry Standard: CVA6 is a single-issue, in-order design maintained by the OpenHW Foundation (with Thales).
\item \small Versatility: Ideal for ISA extensions (Virtualization), prototyping, and integration into complex multi-core structures like OpenPiton.

\begin{frame}[label={sec:orgf3615aa}]{Contexto}
\framesubtitle{Evaluación de la energía consumida por el middleware IoTvar}
\begin{itemize}
\item Para 2025, se esperan 100 mil millones de dispositivos IoT, con un impacto significativo en el consumo energético.
\item Un \emph{middleware} consciente de la energía optimiza el consumo del hardware al gestionar eficientemente el software.
\item \alert{IoTvar} es un middleware de IoT que predice el consumo energético, pero solo para periodos de tiempo fijos.
\end{itemize}

\begin{frame}[label={sec:org21a5e5f}]{Problema y objetivos de la investigación}
\begin{alertblock}{Problema}
\small El modelo energético del estado del arte para middleware de IoT tiene tiempo de ejecución fijo y requiere calibración manual, lo que limita su uso más allá de entornos experimentales controlados.
\end{alertblock}
\begin{exampleblock}{Objetivos de la investigación}\label{sec:orge49c019}
\small Nuestro objetivo es desarrollar un nuevo modelo energético para IoTvar que introduzca el tiempo como variable, permitiendo ajustar dinámicamente estrategias de consumo energético durante la ejecución.

\begin{itemize}
\item \small \textbf{RQ1} ¿Cómo mejora la inclusión del tiempo como variable en el modelo energético la precisión de las predicciones de consumo de energía para el middleware IoTVar que se ejecuta en dispositivos que funcionan con baterías?
\end{itemize}
\end{exampleblock}
\end{frame}

\section{Amenazas a la validez, conclusiones y trabajo futuro}
\label{sec:org2974098}

\begin{frame}[allowframebreaks]{Amenazas a la validez, conclusiones y trabajo futuro}
\begin{block}{Amenazas a la validez}
\begin{itemize}
\item \small Precisión de las mediciones de consumo energético
\item \small Tasas de refresco variables en el middleware IoTvar
\item \small Limitaciones en los parámetros de IoTvar para monitoreo de energía
\end{itemize}
\end{block}
\begin{block}{Conclusiones}
\begin{itemize}
\item \small La inclusión del tiempo como variable en el modelo energético genera un modelo más general sin comprometer la precisión.
\item \small Las variables de IoTvar permiten predecir el consumo energético en función del tiempo.
\end{itemize}
\end{block}
\begin{block}{Trabajo Futuro}
\begin{itemize}
\item \small Realizar experimentos ejecutando el middleware IoTvar en otras placas (Odroid, BananaPi, etc.).
\item \small Automatizar el procedimiento para determinar la frecuencia de muestreo en diferentes dispositivos.
\item \small Ejecutar los experimentos en condiciones de temperatura controlada.
\item \small Evaluar la incorporación de variables físicas, como la temperatura, en la predicción del consumo energético.
\end{itemize}
\end{block}
\end{frame}
